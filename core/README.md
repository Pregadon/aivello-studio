# @posol/core

Ядро «Посла»: мережі, де ШІ-посол веде акаунт людини за її мандатом і домовляється з послами інших людей.

Тут немає інтерфейсу і бази даних, лише правила, які мають працювати однаково і на сервері, і в застосунку:

| Модуль | Що робить |
| --- | --- |
| `src/mandate.ts` | Рушій політик: для кожного наміру посла вирішує, виконати, передати людині чи заборонити |
| `src/seal.ts` | Ключі Ed25519, підписи людини і посла, печатка людини на тексті |
| `src/protocol.ts` | Повідомлення посол-посол (REQUEST, OFFER, COUNTER, ACCEPT, DECLINE, WITHDRAW) і стани потоку |
| `src/journal.ts` | Журнал дій, у який лише дописують; скасування протягом 24 годин |
| `src/attention.ts` | Застава за перший контакт з незнайомцем і денний ліміт нових контактів |
| `src/brain.ts` | Інтерфейс мозку посла, простий алгоритм торгу і запобіжник меж |
| `src/shop.ts` | Вбудований магазин: вимкнений з коробки, активація, товари, публікація за $5 |
| `src/stripe.ts` | Оплата публікації магазину через Stripe Checkout і перевірка підпису вебхука |
| `src/network.ts` | Комутатор MVP: доставка повідомлень між послами і каталог опублікованих магазинів |
| `src/embassy.ts` | Посольство: усе разом, плюс дії, які потребують підпису людини |
| `src/state.ts` | Знімок стану посольства для бази і відновлення після перезапуску |

## Запуск

Потрібен Node.js 22.18 або новіший: він виконує TypeScript без збірки.

```sh
npm test             # 28 тестів
npm run demo         # посли торгуються за велосипед
npm run demo:shop    # Оля відкриває магазин, посол Андрія купує рюкзак
npm install && npm run typecheck   # перевірка типів (потрібен typescript)
```

## Головні правила, які гарантує код

- Посол нічого не робить напряму. Кожна дія проходить `evaluate()` і потрапляє в журнал.
- Мандат, рішення з депеші, режим тиші і цілі торгу приймаються лише з підписом ключа людини. У посольства цього ключа немає.
- Підпис посла ніколи не проходить як підпис людини: вид підписувача входить у підписані дані.
- Будь-який хід мозку перевіряє `enforceBounds()`. Навіть якщо мозок «переконали» продати дешевше, код не дасть вийти за межу, яку задала людина.
- Сфери «Особисте» і «Договори» закріплені за людиною, і змінити це не можна.

## Магазин

Магазин є в кожному посольстві з коробки, але вимкнений (`inactive`).

1. Людина активує його (`activate`) — він стає чернеткою (`draft`).
2. Заповнює назву, опис і товари. `shop.missing()` показує, чого ще бракує.
   Посол може сам підготувати товар (`draftProduct`), але додасть його за правилами сфери «Публікації», тобто за замовчуванням лише після згоди людини.
3. Публікує (`publish`): з людини разово списується $5 через `PaymentGateway`. Повторна публікація після змін безкоштовна.

Після публікації товари з'являються в каталозі (`net.searchProducts`). Посли покупців торгуються з послом продавця в межах `minPriceUAH`, а продаж зменшує залишок. Якщо угоду скасовано, залишок повертається. Активувати, змінювати і публікувати магазин можна лише з підписом людини.

### Оплата через Stripe

1. `embassy.startShopCheckout(підпис людини)` створює сесію Stripe Checkout на $5 і повертає посилання на оплату.
2. Людина платить на сторінці Stripe.
3. Stripe надсилає вебхук `checkout.session.completed`. `handleStripeWebhook(тіло, заголовок Stripe-Signature, секрет вебхука, пошук посольства)` перевіряє підпис і публікує магазин. Повторна подія нічого не ламає, а оплата за чужу сесію чи меншу суму відкидається.

Що потрібно для запуску:

- `STRIPE_SECRET_KEY` — секретний ключ (`sk_test_…` для тестів) з [Stripe Dashboard → Developers → API keys](https://dashboard.stripe.com/test/apikeys).
- `STRIPE_WEBHOOK_SECRET` — секрет вебхука (`whsec_…`) після додавання ендпоінта з подією `checkout.session.completed`.
- HTTP-ендпоінт для вебхука є в `../server` (`POST /v1/stripe/webhook`).

Для тестів і демо лишається `FakePaymentGateway`, який нічого не списує.
