# @posol/server

HTTP API «Посла»: зберігає посольства в PostgreSQL, приймає команди з підписом людини і вебхук Stripe.
Без фреймворку, лише `node:http` і `pg`. Node 22.18+ запускає TypeScript напряму, збірки немає.

## Запуск

```sh
npm install
export POSOL_MASTER_KEY=$(openssl rand -hex 32)   # шифрує ключі послів у базі; збережи його в секретах
export DATABASE_URL=postgres://user:pass@host:5432/posol
export STRIPE_SECRET_KEY=sk_test_…               # Stripe Dashboard → Developers → API keys
export STRIPE_WEBHOOK_SECRET=whsec_…             # після створення ендпоінта вебхука
export ANTHROPIC_API_KEY=sk-ant-…                # мозок послів на Claude (console.anthropic.com → API Keys)
npm start                                        # PORT=8080 за замовчуванням
```

Без `DATABASE_URL` сервер працює в пам'яті (усе зникає після зупинки). Схема створюється сама при старті (`schema.sql`).

У Stripe додай ендпоінт `https://<твій-домен>/v1/stripe/webhook` з подією `checkout.session.completed`.
Для локальної перевірки: `stripe listen --forward-to localhost:8080/v1/stripe/webhook`.

## Мозок послів

Якщо задано `ANTHROPIC_API_KEY`, посли торгуються через Claude (`src/claude-brain.ts`), інакше — простим алгоритмом з ядра.
`POSOL_BRAIN=claude|simple` вибирає явно, `POSOL_MODEL` змінює модель (за замовчуванням `claude-opus-5-5`, effort `medium`).

- Модель повертає лише хід — `COUNTER` з ціною, `ACCEPT` або `DECLINE` — у строгій JSON-схемі. Вільного тексту немає, тож вона не може нічого повідомити іншій стороні, зокрема межу людини.
- Кожен хід проходить запобіжник ядра `enforceBounds`: модель, яку обдурили, все одно не погодиться за межею людини.
- Примітка від іншого посла потрапляє в запит лише як дані в окремому тезі; спроба закрити тег вирізається.
- Якщо модель відмовить через безпекові фільтри, API саме повторює запит на рекомендованій запасній моделі (`fallbacks: "default"`).
- Якщо Claude недоступний (мережа, ліміти), хід робить простий алгоритм, а в журналі посла з'являється запис «Мозок посла не відповів».
- Кожен хід — окремий виклик API, тож торг на кілька раундів займає секунди і коштує грошей.

## Як захищено

- **Кожна зміна підписана людиною.** Тіло запиту — документ `Signed<…>` з ключа на телефоні. Підпис перевіряє ядро; підпис посла не пройде як людський.
- **Підпис діє 10 хвилин і лише один раз.** Хеш кожного прийнятого підпису записується в `human_nonces`, тож перехоплений запит не повторити.
- **Читання теж з підписом.** Заголовок `Authorization: Posol <base64url(JSON підписаного {embassy, op:"read"})>`, діє 5 хвилин.
- **Ключі послів зашифровані** AES-256-GCM майстер-ключем; ідентифікатор посольства входить у перевірку, тож ключ одного не підставити іншому.
- **Мінімальна ціна продавця** не з'являється ні в каталозі, ні в публічному вигляді магазину.
- **Вебхук Stripe** перевіряється за сирим тілом; кожна подія обробляється один раз (`stripe_events`). Подію, яку не можна застосувати (чужа сесія), записуємо і відповідаємо 200, щоб Stripe не повторював її днями.
- **Усе або нічого.** Зміни одного запиту (посольства, реєстр застав, підпис, подія Stripe) пишуться однією транзакцією. Якщо база впала, стан у пам'яті повертається до записаного, а той самий підпис можна надіслати ще раз.

## API

| Метод і шлях | Тіло | Що робить |
|---|---|---|
| `GET /healthz` | | Перевірка, що сервер живий |
| `POST /v1/embassies` | `Signed<{embassy, op:"register", name, humanPublicKey}>` | Створює посольство. `humanPublicKey` — 32 байти Ed25519 у base64url; реєстрацію підписано цим самим ключем |
| `GET /v1/embassies/:id` | токен читання | Мандат, магазин, депеша, рішення, що чекають |
| `GET /v1/embassies/:id/journal?since=ISO` | токен читання | Журнал дій посла |
| `POST /v1/embassies/:id/shop` | `Signed<ShopCommand>` | activate, profile, add, update, remove, publish, unpublish |
| `POST /v1/embassies/:id/shop/checkout` | `Signed<{op:"checkout", successUrl, cancelUrl}>` | Повертає `checkoutUrl` на оплату $5 (або публікує, якщо вже сплачено) |
| `POST /v1/embassies/:id/decisions` | `Signed<{proposal, approve}>` | Рішення людини з депеші |
| `POST /v1/embassies/:id/mandate` | `Signed<MandateChange>` | Зміна мандату |
| `POST /v1/embassies/:id/quiet` | `Signed<{quiet}>` | Режим тиші |
| `POST /v1/embassies/:id/sell` | `Signed<{goal}>` | Дозвіл продавати в межах ціни |
| `POST /v1/embassies/:id/buy` | `Signed<{goal, seller}>` | Дозвіл купити; посол відкриває переговори |
| `GET /v1/catalog?q=` | | Пошук товарів в опублікованих магазинах |
| `POST /v1/stripe/webhook` | сире тіло від Stripe | Підтвердження оплати і публікація магазину |

Помилки: 400 поганий запит, 403 немає підпису людини, 404 немає посольства, 409 підпис уже використано, 413 тіло понад 64 КБ, 422 ядро відмовило (магазин, протокол, застава), 502 Stripe відмовив.

## Обмеження цієї версії

- Один процес: запити виконуються по черзі, стан мережі тримається в пам'яті й записується після кожної зміни. Для кількох процесів потрібне блокування по посольству.
- Журнал лежить усередині знімка посольства. Коли він виросте, його варто винести в окрему таблицю.
- Посли торгуються всередині запиту, який почав угоду, і поки Claude думає, інші запити чекають у черзі. Далі торг варто винести у фонову чергу.
- Немає обмеження частоти запитів і реєстрацій; перед публічним запуском його треба поставити (на балансувальнику або в коді).
